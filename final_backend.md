## 1. What "industry ready" means here, and the three words

Antar is an **intelligence layer over the FIR record**, not a chatbot with a database
attached. The product promise is three verbs, and each one already has a spine in the
code — the roadmap in §6 is about what each still lacks.

| | Promise | What exists today | The honest gap |
|---|---|---|---|
| **Think** | Ask in English or Kannada, get an answer that is *from the record* or an explicit refusal | T1–T23 deterministic templates, registry-derived vocabulary, resolve-or-refuse, constitution enforced in code (`app/core/antar_identity.py`), **golden suite 35/35** | ~~No durable case file~~ — **closed 2026-09-25** (P1-3): `SqliteSaver`, thread survives a real process exit |
| **Connect** | Link cases, suspects, MOs, money and places, and say *why* they are linked | Hybrid BM25 + dense retrieval fused by **RRF** (`hybrid_index.py`), cross-encoder rerank, MMR, Adamic-Adar link prediction, evidence ledger, adversarial-audit base-rate audit | ~~the Brain holds 3 rows locally~~ (P1-2: **100,000 FIRs, ~110 ms**); ~~`brain` and `osint` have no graph node~~ (**closed 2026-09-25**, P1-4). Remaining: entity resolution is still a **heuristic** (Jaro-Winkler + Soundex, hard 0.82 cut-off) with no calibrated probability — that is P2-2 |
| **Anticipate** | Where is crime most likely next week, how sure are we, and why | Poisson GLM + split-conformal bands + Gi\*, rolling back-test, **PAI 14.2, top-5% of beats catch 40.4%**, model card generated from code | Near-repeat was the best-evidenced candidate (§5.2). **Measured and rejected** 2026-09-23: 0 of 60 metrics moved, because weekly counts over beats cannot express a day-and-metre kernel. A real triggering term needs event-level times — a data question before a model one |

"Industry ready" for an Indian police deployment means four things beyond features, and
these are what §6 Phase 3 is about: **provenance** (every number traceable to rows),
**privacy** (DPDP Act 2023), **interoperability** (CCTNS/ICJS), and **survivability**
(backups, restart-safety, a deployment that fits the box).

## 2. Non-negotiables — every change is additive, reversible, tested

Unchanged from v1, and it has held: 1,170 tests pass, no route was removed, every runtime
swap sits behind a flag with the old path intact.

1. **No router, endpoint or feature is removed.** Full checklist in §9.
2. **Every runtime swap is a feature flag, not a rewrite.** `ANTAR_BRAIN_BACKEND=torch`
   still restores the torch path in five seconds; `torch` stays in `requirements.txt`.
3. **`main.db` is never mutated destructively.** The rebuilt database is an *additional*
   file; the damaged original is untouched.
4. **`python -m pytest -q` stays green after every step**, not just at the end.
5. **The golden suite and the forecast back-test are re-run and diffed** after anything
   touching routing, retrieval or the database. A regression on either stops the line.

## 5. Research foundation

Each item says what it **confirms** (leave alone) or **changes** (do this).

### 5.1 Open Knowledge Format — the shape of Antar's exportable knowledge

[OKF](https://cloud.google.com/blog/products/data-analytics/how-the-open-knowledge-format-can-improve-data-sharing)
(Google Cloud, v0.1 June 2026, v0.2 September 2026) packages knowledge as a directory of
Markdown files with YAML frontmatter, cross-linked by ordinary Markdown links into a
graph. **Only `type` is required**; `title`, `description`, `resource`, `tags`,
`timestamp` are optional. `index.md` gives progressive disclosure, `log.md` a change
history. Vendor-neutral, no SDK, readable in any editor.

**Why this matters for Antar specifically:** Antar already writes executable
documentation — `AGENTS.md` is parsed by `app/agents/manifest.py` and a test fails the
build when the document and the compiled graph disagree. OKF is the same instinct with a
published envelope. A `knowledge/` bundle (crime taxonomy and the 121 concepts over 142
`CrimeGroup_Name` values, the BNS/IPC mapping, MO vocabulary, the constitution, the
forecast model card, the agent manifest) makes Antar's *understanding* portable: a
reviewer, an auditing officer, or another department's agent can read it without Antar
running. **Changes: add an OKF export (§6 P2-1).**

### 5.2 Self-exciting point processes — the best-evidenced forecast upgrade

Mohler, Short, Brantingham, Schoenberg & Tita, *Self-Exciting Point Process Modeling of
Crime*, JASA 106(493), 2011 ([PDF](http://www.stat.ucla.edu/~frederic/papers/crime1.pdf)),
and [spatial-covariate extensions](https://arxiv.org/pdf/1708.03579). Crime is partly
**self-exciting**: one burglary raises the short-term risk nearby (near-repeat
victimisation), so the intensity is a stable background plus a decaying kernel triggered
by recent events. Reported result: with **10% of a city flagged, the point process caught
660 of 2,627 crimes against 547 for a prospective hotspot map (+21%)**, and it held even
for offence types where near-repeat effects are weaker.

**Against Antar's model:** the current GLM uses recent weeks, same week last year,
neighbouring units, wider area and season — all *level* signals. None of them encode
"something happened **here, three days ago**". Antar has 383k geocoded real FIRs with
dates (no times), which is enough for a day-resolution triggering term.
**Changes: add a near-repeat feature (§6 P1-1) — and prove it or drop it, against the
existing 23-week back-test and PAI, which is exactly the harness for this question.**

### 5.3 Probabilistic record linkage — calibrated links instead of a threshold

Fellegi & Sunter, *A Theory for Record Linkage*, JASA 1969; modern implementation
[Splink](https://moj-analytical-services.github.io/splink/) (UK Ministry of Justice,
Fellegi-Sunter with EM-estimated parameters, **a million records in about a minute on a
laptop**, SQL backends including DuckDB).

**Against Antar's code:** `app/services/entity_resolver.py` scores with Jaro-Winkler plus
Soundex and cuts at a hard `0.82`. That number is a judgement call, not a probability,
and it cannot tell an officer *how likely* two records are the same person — which is
precisely the question in court. Fellegi-Sunter gives a **match weight per field**
(learned m/u probabilities) that decomposes into "the surname agreed, which is worth this
much; the district agreed, which is worth almost nothing because everyone matches on it".
**Changes: an FS scorer for suspect/accused linkage (§6 P2-2), additive beside the
existing matcher, not replacing it.**

### 5.4 Small aligned models beat big general ones — and SemIf's logit trick

Ouyang et al. 2022 (InstructGPT, `D:\local_AI\researach_paper\LLM-LM.pdf`): the **1.3B
aligned model was preferred to 175B GPT-3 85±3% of the time**, and alignment cost ~60
petaflop/s-days against 3,640 for pretraining. [SemIf](https://github.com/TheoLeeCJ/SemIf)
reads typed option probabilities straight off one forward pass instead of generating
JSON — **5.2× faster**, no parse failures, and it runs quantised on CPU.

**Confirms:** do not put a general chat model on-box. QuickML stays the generative path;
the deterministic templates stay primary. **Possible change (P3, only with headroom):** a
sub-1B Q4_K_M router for T1–T23 selection via logit readout. Q4_K_M holds 85–95% of
quality at ~30% of memory — but only after the image loses torch.

### 5.5 Retrieval — research confirms what is already built

RRF hybrid retrieval is [consistently better than either constituent](https://arxiv.org/html/2604.01733v1)
(+7.4% NDCG on WANDS; BM25 still beats strong dense models on many metrics in 2026, which
is why fusion wins). **Antar already does exactly this**: `app/services/hybrid_index.py`
implements Okapi BM25 over an inverted index and RRF-fuses it with dense ranks;
`retrieval.py` fuses at alpha 0.7/0.3, then cross-encodes, then MMR-diversifies.
**Confirms — do not touch the retrieval stack.** The gap is not the algorithm, it is that
the index has three rows (§6 P1-2).

Also confirmed as correctly chosen and cited in `docs/footprint/` and the model card:
Chainey et al. 2008 (PAI), Getis & Ord 1992 (Gi\*), Vovk/Lei (split-conformal),
Carbonell & Goldstein 1998 (MMR), Adamic & Adar 2003 (link prediction), Jégou et al. 2011
(product quantisation, for later Brain scale), Reimers & Gurevych 2019 (cross-encoders).

### 5.6 Deployment context — CCTNS, ICJS and DPDP

[CCTNS](https://www.mha.gov.in/sites/default/files/CCTNS_Briefportal24042018.pdf)
interconnects **16,276 police stations** (100% deployed, 97% connected).
[ICJS](https://www.mha.gov.in/en/commoncontent/inter-operable-criminal-justice-system-icjs)
integrates Police, Courts, Jails, Forensics and Prosecution over a **Data Sharing Matrix
approved by the Supreme Court's e-Committee**. The
[DPDP Act 2023](https://en.wikipedia.org/wiki/Digital_Personal_Data_Protection_Act,_2023)
governs personal-data processing, with Rules notified in 2025.

**Changes:** Antar's database is already built to the Karnataka Police FIR ER schema —
that is the right foundation. What is missing is the **statement of posture**: a written
mapping from Antar's fields to CCTNS entities, a data-processing note against DPDP
(purpose limitation, retention, the redaction already in `guardrails.redact_pii` and
`security.scrub_*`), and an ingest contract that is idempotent and provenance-stamped.
This is documentation and a small amount of code, and it is what turns a datathon build
into something a department can actually take (§6 P3-1).

### P3 — deliberately NOT doing

- **A general-purpose local LLM.** §5.4 is the argument; QuickML is off-box compute.
- **A GNN for link prediction.** The literature ([CrimeGraphNet](https://arxiv.org/pdf/2311.18543),
  [Berlusconi et al. 2016](https://journals.plos.org/plosone/article?id=10.1371%2Fjournal.pone.0154244))
  points at GCNs, but that reintroduces torch for no accuracy requirement we can state,
  and Berlusconi's own method is topological — the family Antar already runs.
- **Replacing SQLite**, rewriting the retrieval stack (§5.5 confirms it), or touching the
  forecast model beyond P1-1.

## 10. The demo, in three sentences

> **Think.** One million real FIRs. Ask in English or Kannada and the answer comes from
> the record — the model never writes SQL and never picks a number, and when Antar cannot
> resolve what you asked, it refuses instead of answering a different question. 35 of 35
> golden questions, mean 656 ms.
>
> **Connect.** It links cases to suspects to money to places, names the shared evidence
> key for every link it asserts, and runs an adversarial base-rate check that can veto its
> own hypothesis before an officer sees it.
>
> **Anticipate.** Where crime is most likely next week, at the beat an officer actually
> patrols, as a calibrated range with its reasons — back-tested the way the field measures
> it: the top 5% of beats caught 40% of the next week's crime, 52% for property crime,
> better than last month's hotspots in 23 weeks out of 23. And it does all of this on a
> CPU, in under 2 GB, with no GPU and no frontier model — because it has to run in a
> police IT environment, not a data centre.
